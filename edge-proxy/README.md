# 🌉 מתווך-הקצה — "רק הקישור שלי, אפס בקשות מהסינון"

**הכרעת-בעלים 12.8:** כל תעבורת-הגוגל של האפליקציה עוברת דרך הדומיין המאושר
(`api.buildsmart-il.com`). הלקוח מדבר **רק** עם הדומיין שלך; המתווך פונה לגוגל
מאחורי-הקלעים. הסנן רואה דומיין אחד — שלך.

## מה זה נותן — ומה הקושי היחיד (בכנות)

| שירות | דרך המתווך? | הערה |
|---|---|---|
| 🖼 תמונות + קטלוג | ✅ כבר חי | ‏cdn.buildsmart-il.com + same-origin |
| 🗄 נתונים (Firestore) | ✅ בונים | ל-SDK יש הפניית-host רשמית ⇒ נקי |
| 🔑 התחברות (Auth) | ✅ בונים | ל-SDK **אין** הפניה ⇒ מחליפים את שכבת-הרשת ב-REST דרך המתווך (יותר עבודה, אבל **דרך הדומיין שלך — לא הסנן**) |
| ⚙️ פעולות-שרת (functions) | ✅ בונים | קריאת-REST דרך המתווך |

**אין שום נתיב שדורש בקשה מהסנן.** הקושי היחיד הוא שהתחברות דורשת קצת יותר
קוד (עוקפים את ה-SDK, לא את הסנן).

## פריסת המתווך (בעלים · ~5 דקות, אפס נגיעה באפליקציה החיה)

1. Cloudflare ← **Workers & Pages** ← **Create** ← **Worker** ← שם: `bs-edge`.
2. **Edit code** ← מחק את התבנית ← הדבק את `worker.js` ← **Deploy**.
3. **Settings** ← **Domains & Routes** ← **Add** ← **Custom Domain** ←
   `api.buildsmart-il.com` (קלאודפלייר מוסיף DNS לבד — אותו חשבון).
4. בדיקה: פתח `https://api.buildsmart-il.com/evil` — צריך להחזיר **404**
   (ה-allowlist עובד); `…/fs/` יחזיר תשובת-Firestore.

זהו. תת-דומיין חדש; האפליקציה החיה לא מושפעת עד שדגל-הלקוח נדלק.

## חיווט-הלקוח (ארכיטקט · מאחורי דגל-קומפילציה `EDGE_PROXY`, כבוי כברירת-מחדל)

כבוי ⇒ פריסה **ביט-זהה להיום** (אפס רגרסיה). דלוק ⇒ כל שירות מופנה למתווך:

- **Firestore:** `FirebaseFirestore.instance.settings = Settings(host:
  'api.buildsmart-il.com/fs', sslEnabled: true, webExperimentalForceLongPolling: true)`
  — long-polling כי הוא HTTPS פשוט שהמתווך מעביר נקי (streams/gRPC שבירים דרך proxy).
- **Auth:** החלפת שכבת-הרשת של email/password ל-Identity-Toolkit REST מול
  `…/idt/…` (buildsmart משתמש רק ב-email/password ⇒ בר-החלפה). ניהול-סשן
  עצמאי; ה-idToken נשלח ל-Firestore-proxy.
- **Functions:** קריאת-REST ל-`…/fn/<name>` עם ה-idToken ב-Authorization.

## אבטחה (אינווריאנט)

המתווך הוא **allowlist** — מעביר אך ורק לארבעת ה-hosts של גוגל שהאפליקציה
צריכה; כל שאר ה-paths ⇒ 404. הוא **לא** open-proxy ⇒ הדומיין לא הופך לטאנל-כללי,
והאישור-הגורף של הדומיין נשאר תקף. ‏CORS מוגבל ל-`buildsmart-il.com` בלבד.

## סדר ביצוע

1. **בעלים:** פריסת ה-Worker (למעלה) — עצמאי, בטוח, אפס-סיכון.
2. **ארכיטקט:** חיווט Firestore מאחורי `EDGE_PROXY` (דורמנטי) + ratchet.
3. **בעלים:** בדיקה על קו-מסונן עם הדגל דלוק — נתונים עובדים דרך הדומיין.
4. **ארכיטקט:** REST-Auth (החלק העמוק) — אחרי ש-Firestore הוכח.

**גבול:** אין החלפות-DNS על הדומיין הראשי; המתווך על תת-דומיין חדש. אפס נגיעה
ב-`firebase.json`/functions של הפריסה החיה (בניגוד למסלול Cloud-Run — Worker
נקי יותר). לקח 19: קודם מוודאים, אז מעבירים תנועה.
