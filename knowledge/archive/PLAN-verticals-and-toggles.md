# תוכנית: חבילות-ורטיקל + טוגלי-פיצ'רים ל-**בנייה חכמה** (בהשראת מאור)

> **היעד:** להפוך את BuildSmart-Clean מ"פרופיל-בקומפילציה" ל**פלטפורמה-שמתקינים-לפי-סוג-עסק** —
> בוחרים **חבילת-ורטיקל** (מונחים + מודולים) + מכוונים **טוגלי-פיצ'רים** גרנולריים + ממתגים → אפליקציה תפורה.
> **בדיוק כמו מאור (`verticalPacks.ts` + `config.ts featureOn/termOf` + אשף), מותאם ל-Flutter/Riverpod.**
> **ביצוע:** הצי, רב-פעמי · **עקרונות:** additive · מאחורי דגל · הקיים זהה-בייטים · שער-ירוק · toggle-matrix.

---

## 🌉 הגשר הארכיטקטוני (מה יש → מה צריך)
**יש כבר (הצי בנה):** `APP_PROFILE` (קומפילציה: demo/buildsmart/clean/company2) · `AppBrand` (מיתוג→קובץ) · `orgId` רב-דיירות · ייבוא-קטלוג-CSV.
**מה חסר (מה שמאור המציא):** שכבת-**config בזמן-ריצה** (`modules` + `features` + `terms`) · `featureOn/termOf` · `verticalPacks` · אשף-הקמה.
**העיקרון:** להוסיף **שכבת-`OrgConfig` ריצתית מעל** היסוד-הקומפילציה. הפרופיל נשאר ה-**default/base**; ה-config מתלבש מעליו. *(ריצתי = אפשר אשף + שינוי בלי build מחדש — זה מה שמאור עשה נכון.)*

---

## השלבים (V1→V6 · רב-פעמי לצי)

### V1 · יסוד-config ריצתי (הבסיס לכל השאר)
- **V1.1** מודל `OrgConfig` ב-Dart: `{ slug · orgName · theme · modules{} · features{} · terms{} }` (מראה את מאור).
- **V1.2** **loader null-safe** (מאור `loadOrgConfig`): סדר-רזולוציה — override-בעלים → config-לפי-חברה (מ-`orgId`/asset) → **DEFAULT**. שבור/חסר → DEFAULT, לא קריסה.
- **V1.3** `orgConfigProvider` (Riverpod) שכל האפליקציה קוראת.
- **DoD:** config ברירת-מחדל = **התנהגות בנייה-חכמה הנוכחית, זהה-בייטים** · מאחורי דגל `ORG_CONFIG`.

### V2 · 🎛️ טוגלי-פיצ'רים גרנולריים ← *מה שביקשת*
- **V2.1** `featureOn(cfg, key)` — **חסר=דלוק · רק false מכבה · כיבוי-מודול משורשר לילדיו** · core תמיד-דלוק (מאור, מילה-במילה בלוגיקה).
- **V2.2** **מיפוי-מודולים+פיצ'רים** של בנייה-חכמה למפתחות: `catalog · orders · dive · compat · search · manager · supplier · courier · worker · finance · rewards · intel · chat · site …` (+ תת-פיצ'רים: `manager.approvals`, `finance.credit`, `catalog.import` …).
- **V2.3** חיווט: כל מסך/פיצ'ר בודק `featureOn` לפני mount/הצגה.
- **V2.4** ⭐ **toggle-matrix e2e** (כמו מאור/clean-two-links): לכל פרופיל-חבילה → מזריק config → מריץ זרימות-אמת → אפס-שגיאות. **ההוכחה ש"כל צירוף נשאר מחווט".**
- **DoD:** הכל-דלוק כברירת-מחדל = התנהגות נוכחית · כל טוגל עובד · toggle-matrix ירוק.

### V3 · 🏷️ מילון-מונחים (מיתוג-מחדש פר-ורטיקל)
- **V3.1** `termOf(cfg, key, fallback)` (מאור) — דריסה-ריקה=ברירת-מחדל.
- **V3.2** מפתחות-מונח לתוויות-המשתמש: `nav.customers`, `entity.customer`, `entity.order`, `entity.supplier`, `nav.catalog` …
- **V3.3** חיווט התוויות דרך `termOf` (ברירת-מחדל = המחרוזות הנוכחיות, **זהה-בייטים**).
- **DoD:** בלי-terms = טקסט נוכחי · עם-terms = ממותג. **דו-קיום עם Studio** (Studio עדיין דורס, מנצח).

### V4 · 📦 חבילות-ורטיקל (הכותרת)
- **V4.1** `VerticalPack { id · emoji · label · terms{} · modules{} }` + `VERTICAL_PACKS[]` (מאור).
- **V4.2** **חבילות לבנייה-חכמה** (החלטת-בעלים) — למשל: **ספק-חומרי-בניין** (ברירת-מחדל) · אינסטלציה · חשמל · כלים/חומרה · קרמיקה/אריחים · קבלן-כללי. כל חבילה = terms+modules.
- **V4.3** `applyVerticalPack(cfg, pack)` — **החלפה מלאה** של terms+modules (נקודת-פתיחה דטרמיניסטית), שאר-הconfig נשמר (מאור).
- **DoD:** בלי-חבילה = נוכחי · החלת-חבילה = בסיס-תפור, הפיך.

### V5 · 🔌 אשף-הקמה (מנהל-על בלבד)
- **V5.1** אשף באפליקציה (מנהל/super-admin לפי מייל): **בחר-ורטיקל → כוונן-טוגלים → מַתֵּג → שמור.**
- **V5.2** **ייבוא/ייצוא-config** לעריכה-חוזרת (מאור `b5dcd7e2`).
- **V5.3** האשף כותב את ה-`OrgConfig` שה-V1–V4 צורכים (per-`orgId`).
- **DoD:** מנהל מקים חברה-חדשה מהאשף, בלי קוד · הקטלוג נשפך ב-CSV (הseam הקיים).

### V6 · ✅ הוכחה
חברה שנייה **בורטיקל שונה** (למשל "אינסטלציה") מהאשף → deploy לערוץ-נפרד → **לינק**. עכשיו 2 הלינקים שונים לא רק בשם/קטלוג אלא ב**כל הזהות** (מונחים+מודולים). מרחיב את `clean-two-links`.

## 🛡️ הגנות (כל שלב)
additive · מאחורי דגל `ORG_CONFIG` · **הקיים זהה-בייטים** (ברירת-מחדל=נוכחי) · המנועים לא-זזים · שער-ירוק · mutation-verify · **toggle-matrix** לכל שינוי-טוגל.

## ⚠️ הערות-יושר
1. **הקפיצה האמיתית = קומפילציה→ריצה** (V1). זו העבודה המרכזית; אחריה האשף+חבילות "מתלבשים" בזול.
2. **סטאק:** מאור=React/config.ts · אנחנו=Flutter/Riverpod → **לוגיקה עוברת, קוד מומש-מחדש ב-Dart.**
3. **דו-קיום עם Studio** — ה-terms/toggles משלימים את Studio, לא מתנגשים (Studio דורס נקודתית).
4. **ורטיקל באותו-עולם (סחר/חומרי-בניין) = זול** (המנוע חל ישר). **תעשייה-שונה-לגמרי** = דורש גִּנֵּרוּג-מנוע (dive/compat) — פרויקט נפרד, לא בתוכנית הזו.

## DoD כולל
בנייה-חכמה מותקנת **מאשף לפי-סוג-עסק**: חבילת-ורטיקל + טוגלים + מיתוג + קטלוג-CSV → אפליקציה תפורה · הכל additive/הפיך · הקיים זהה-בייטים · toggle-matrix ירוק · הוכחה ב-2 ורטיקלים-שונים.

V1 (יסוד) → V2 (טוגלים + matrix) → V3 (מונחים) → V4 (חבילות) → V5 (אשף) → V6 (הוכחה). כל שלב פרוסה/פרוסות, בייטים+שער לכל אחת.
