## הוכחת-החוזה (עכשיו כנה)

The <=6 proof is now HONEST in three ways the v1 oracle was not. (1) TARGET HIDDEN: every census (steps 29, 42, 51, 89) runs an exhaustive info-gain BFS to depth kMaxDiveTurns where the walker selects the next chip purely by the engine's own _AxisScore/distinctCardCount gain and NEVER receives the target sku as a selection input — proven by a code-structure guard plus a mutation test (feeding a wrong target yields the identical chip sequence). v1's greedy oracle that peeked at which chip contained the target is deleted. (2) SURVIVAL not guess: success is 'the target sku is INSIDE the <=12 ShowProducts cut reached by turn <=5 (kListThenPickTurn) so the grid pick is the <=6th action', not 'the engine's single best guess equals the target'. The list is capped at kReachListCap=12 (NOT 30) and its labels must be pairwise-distinct (distinctSelectionLabels), with a self-test injecting a 13-item/turn-7 list that goes RED (step 50). (3) EMPTY allowlists by construction: kReachAllowlist (step 1), the census unreachable allowlists (29/42/51), and the <=4 over4Allowlist + kHopPairOverride (62/89) are all asserted .isEmpty — any debt is tracked in a SEPARATELY-named list the gate ignores, so the gate cannot be quietly satisfied by widening an allowlist. The denominator is the single uncapped kReachUniverse (distinct-by-card, no .take()/.sublist(), lower-bound pinned) — counted via divePoolBySku>_collapseKey, NEVER raw kDivePool.map(sku), killing the inflated-100% unit-mismatch. The <=4 contract is honestly scoped as '<=4 to a RELATED product over the tagged navigational graph (compat∪variant∪kit∪category, no cross-WaterSystem)', proven by a DIRECTED all-pairs BFS over the SAME rankedNeighborsOf adjacency the UI actually renders — the leaf>hub>superHub>hub>leaf=6 arithmetic of v1 is replaced by a 1-adjacent multi-superHub STAR (every hub exactly 1 edge from a superHub, superHubs mutually 1-adjacent, out-degree <= budget), with proof-edges rendered in an UNBOUNDED sub-rail so the constructive path is always physically tappable, and a self-test that deletes a superHub<->superHub edge to force an over-4 pair RED. The gate itself is REAL: scripts/verify_unified_finder.sh and scripts/verify_card_keyboard.sh are BASH (modeled on the existing scripts/audit_gates.sh / mutation_verify.sh), they EXECUTE flutter test on the bash CI (v1's .ps1 never ran on ubuntu and therefore always 'passed'), each carries a self-test that injects a >4/>6 offender and asserts the script exits non-zero, and each greps the live deploy workflows (firebase-hosting.yml, web-deploy.yml) failing if any monster dart-define leaks. The human-realistic acceptance track (step 30) runs ALONGSIDE the math gate: a ~20-phrase naive-mouth corpus asserts reading-cost turns <= kMaxDiveTurns and that screen-1 presents exactly kMaxScreen1Decisions==1 decision group.
