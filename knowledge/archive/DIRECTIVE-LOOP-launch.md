## 🔌 U3.3 — פירוט: מסך-בעל-חנות = "מייבא-קוד-בינה" (לא הקלדה ידנית)
**רקע (מאומת במחקר):** הספק חי ב-**קוד בינה** (מיניסופט) — מערכת-דסקטופ, **בלי API ציבורי**. הדרך היחידה להוציא ממנה נתונים = **ייצוא-קובץ** (Excel/CSV, או "מבנה אחיד" החוקי). לכן U3.3 אינו הקלדה-ידנית — הוא **ייבוא**.

**הזרימה:**
1. הספק מייצא מלאי/מחירון מ-קוד בינה ל-Excel/CSV.
2. מעלה ל-BuildSmart → **מסך מיפוי-עמודות גמיש** (הספק מסמן: איזו עמודה = מק"ט · מחיר · מלאי · שם) — **כי הפורמט לא-ידוע-מראש** (אין לנו דוגמת-ייצוא).
3. `parseCsvToDrafts` (**C4.5 · `supplier_onboarding.dart:170` — כבר קיים!**) → drafts.
4. כתיבה ל-`inventory` **תחת ה-`storeId` של המשתמש** (U3 מאבטח פר-חנות — חנות לא נוגעת בשל אחר).
5. חותמת "עודכן לאחרונה" גלויה לקונה (שקיפות-טריות).

**reuse (לא לבנות מאפס):** `parseCsvToDrafts` (C4.5) · `kTradeImportFlag` (הדגל הקיים) · claim `storeId` (U3.1.1).
**זה פותר את ה-cross-cut:** במקום לממש את `supplierSubmitProvider` כהקלדה-ידנית — בונים **ייבוא**. מסך-המלאי (U3.3.2) מציג/מאפשר-עריכת-שורה, אבל המסה מגיעה מייבוא.
**מיפוי גמיש = חסין-לפורמט:** הספק ממפה פעם-אחת, המיפוי נשמר (per-store), וכל ייצוא עתידי נכנס אוטומטית — עובד עם **כל** פורמט של קוד בינה בלי לדעת אותו מראש.
**עצירה-קשיחה:** אם הייצוא מתגלה כלא-CSV/Excel (למשל רק "מבנה אחיד" בינארי) → עצור ושאל (ייתכן פרסר נפרד).

## פרוטוקול לכל שלב (חזור על זה בלולאה)
1. **קרא** את SPEC §Ux + ההנחיה הפרטנית (אם יש) מענף-הידע.
2. **גראונד מול הקוד החי** — שמות-סימבולים אמיתיים + מוקשים, בדיוק כמו ב-U1/U3 (מה כבר בנוי? מה additive? מה מתנגש?). אל תבנה מה שכבר קיים.
3. **בנה additive:** Dart-חדש מגודר `kUserSystem` (OFF = זהה-בייטים) · שינויי rules/functions = additive-בטוח (לא לשחרר קיים; לוודא שאף משתמש-קיים לא מושפע).
4. **אמת מקומית (חוק-ברזל):** `flutter analyze` = 0 · **סוויטה מלאה ירוקה** · לכל שינוי-rules → **emulator rules-test** (`--test-concurrency=1`) + **mutation-verify** (הזרק באג → RED → שחזר → GREEN).
5. **commit מקומי.** ואז **עצור → בקש "תדחוף".**
6. אחרי הדחיפה: **המתן לאימות-ה-CI שלי** ("ירוק — מאומת") → רק אז התקדם לשלב הבא.
