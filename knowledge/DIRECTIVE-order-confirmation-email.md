# הנחיה: מייל-אישור-הזמנה יפה בסיום-הזמנה

> **אושר ע"י הבעלים** (29/7: "בסיום הזמנה שישלח את ההזמנה יפה למייל").
> **ביצוע:** `claude/whats-happening-LyY9G` · הצי · **מגודר-דגל · default-off** עד שהבעלים מפעיל (זהה-בייטים).
> **מאומת:** יש `customer.email` (`customers_store.dart`) + `functions/src/orderFlow.ts`/`orders.ts`, **אבל אין שום שליחת-מייל בשרת** (grep nodemailer/sendgrid/resend = ריק) → **צריך לבנות.**

---

## מה לבנות
1. **פונקציית-מייל** (חדש — `functions/src/orderEmail.ts`, או הרחבת `orderFlow.ts`): **טריגר על יצירת/סיום-הזמנה** (Firestore `onCreate` של order-doc, או קריאה מ-`placeOrder`/`advanceOrderStage`) → שולח מייל.
2. **תבנית HTML יפה (RTL עברית):** מס'-הזמנה · תאריך · פרטי-לקוח · **טבלת-מוצרים** (שם · כמות · מחיר) · סה"כ · **לוגו-מותג כתום** · פרטי-קשר של העסק · "תודה שהזמנת מבנייה חכמה".
3. **נמענים:** ל**לקוח** (`order.customerEmail` / `customer.email` — **אם קיים**) + **עותק לבעלים/העסק** (תמיד — כדי לדעת שהגיעה הזמנה).
4. **ספק-מייל:** מומלץ **Resend** (free-tier נדיב, API פשוט) · חלופות: Firebase "Trigger Email" extension / SendGrid / SMTP. **⚠️ דורש API-key בקונסול = פעולת-בעלים.**
5. **חיווט:** בסיום-checkout (`store_screen.dart` `placeOrder`) → מפעיל את הזרימה.

## תרחישי-קצה
- **אין מייל-לקוח** (הזמנת-טלפון בלבד) → שלח **רק** את העותק-לבעלים; אל תיכשל.
- ללא API-key → הפונקציה לא-פעילה (degrade), האפליקציה זהה-בייטים.

## 🛡️ בטיחות
- **מגודר-דגל** (`kOrderEmail`/`ORDER_EMAIL`) · **default-off = זהה-בייטים.**
- אין-חשיפת-דאטה מיותרת · rate-limit בסיסי · `central-verify` ירוק.
- הבעלים מספק את ה-API-key; עד אז — רדום.

## DoD
בסיום-הזמנה → **מייל-HTML יפה נשלח ללקוח** (+עותק לבעלים) עם כל פרטי-ההזמנה, לוגו, וסה"כ. מגודר-דגל, default-off עד הפעלת-בעלים. אין-מייל-לקוח → עותק-לבעלים בלבד. שער ירוק.
