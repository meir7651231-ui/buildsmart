## 1. סכימת ה-`dims` — מה כל קטגוריה צריכה (סדר = סדר תצוגה בטבלת "פרטי מוצר")

`dims` הוא `Map<String,dynamic>`. המפתחות הקנוניים (מ-CATALOG-CARD-PROTOCOL §1) + הרחבה
פר-משפחת-מוצר ליפסקי. למלא **רק** מה שמופיע במקור:

### מפתחות-ליבה (לכל מוצר אם קיים במקור)
| מפתח | דוגמה | הערה |
|---|---|---|
| `תיאור` | `ברז כיור פרח ניקל` | כותרת הכרטיס החיצוני (קצר) |
| `שם מלא` | `ברז כיור פרח חרירי חיסכון ניקל מוברש` | כותרת הכרטיס הפנימי |
| `יצרן` | `Lipski` | צ׳יפ + טבלה |
| `מק"ט יצרן` | `LP-2201-N` | טבלה |
| `חומר` | `פליז מצופה כרום` | מפרט + צ׳יפ |
| `צבע` / `גימור` | `ניקל מוברש` | ⚠️ **צבע = גימור-נראה**, לא חומר-הגוף |
| `מידה` / `DN` | `1/2"` · `40` | חתימת-חיבור + צ׳יפ-מידה |
| `אורך` / `מידות` | `30 ס"מ` · `120×60` | צ׳יפ-אורך / טבלה |
| `תקנים` | `ת"י 1385` | תקינות |
| `אריזה` / `משטח` | `qtyPack`/`qtyPallet` (שדות נפרדים, לא ב-dims) | |

### תוספות פר-משפחה (ליפסקי — קטגוריות-המפתח)
- **ברזים** (כיור/קיר/מטבח/אמבטיה/מקלחת): `סוג-חיבור` (קיר/סיפון), `גובה-זרבובית`, `סוג-מנגנון`
  (קרמי/תרמוסטטי), `גימור`, `חיסכון-מים` (אם מצוין).
- **מחסומים/מאספים/תעלות-ניקוז**: `DN`/`קוטר`, `סוג-רשת`, `יציאה` (אנכי/אופקי), `נירוסטה/פלסטיק`.
- **אביזרי-תבריג / שקע-תקע / NTM / HDPE / נחושת**: `מידה` (DN both ends), `סוג-חיבור`
  (פ.פ/פ.ח/ח.ח — נורמליזציה ב-CATALOG-CARD-PROTOCOL §19.1), `חומר`, `לחץ-עבודה`.
- **מושבי-אסלה / אסלות / מסעפים**: `התאמה` (קומפלט/תלייה), `חומר`, `מנגנון-סגירה` (שקט/רגיל), `צבע`.
- **ראשי-מקלחת / מזלפים / זרועות**: `מצבי-זרם`, `קוטר`, `חיבור` (1/2"), `גימור`, `אנטי-אבנית`.

> כלל §15 (מהפרוטוקול): **לא בונים כרטיס פר-מוצר — מנוע אחד + dims לכל מוצר.** עושר-ה-dims
> לכל **קו** הוא הקצב. טבלת-קטלוג אחת → dims לכל שורותיה → עשרות כרטיסים מלאים במכה.

## 2. ⚙️ ה-runbook: "התקבל המקור → 100%" (הצעדים המדויקים)

קלט אפשרי + מסלול. בכל מסלול: **אפס המצאה — verbatim מהמקור.**

### מסלול A — התקבל PDF הקטלוג המלא של ליפסקי (העדיף)
זהה למתודולוגיית פולירול ([CATALOG-CARD-PROTOCOL.md](CATALOG-CARD-PROTOCOL.md) §5,§13,§17):

```bash
# 1. חילוץ טקסט (עם פריסה) + ניקוי bidi
pdftotext -layout lipskey.pdf /tmp/lipskey.txt
sed -E 's/[‎‏‪-‮⁦-⁩​]//g' -i /tmp/lipskey.txt
# 2. כל עמודי-הקטלוג (לא רק 05-30!) → assets/lipskey/pages/
pdftoppm -jpeg -r 110 lipskey.pdf assets/lipskey/pages/page
# 3. תמונות-מוצר (rgb+smask, הרכבה על לבן) — CATALOG-CARD-PROTOCOL §17
```
- **3א.** קרא תוכן-עניינים → מפה סקשנים↔עמודים (⚠️ מיפוי-עמודים: מס׳-PDF ≠ מס׳-מודפס).
- **3ב.** לכל קו/טבלה: helper ממוקד-עמודות (כמו `_acPipe`) → `dims` לכל שורה (§13.1).
- **3ג.** מלא `color`/`qtyPack`/`qtyPallet` היכן שהטבלה נותנת.
- **3ד.** עדכן/הרחב `scripts/extract_lipskey.py` שמייצר את `lipskey_catalog.dart` מ-JSON-ביניים,
  כך שההרצה חוזרת-על-עצמה (idempotent) ולא ידנית.

### מסלול B — התקבל מחירון/אקסל/CSV (טבלת-נתונים)
- מיפוי-עמודות: `sku → מק"ט`, `name`, `מחיר`, `color`, `אריזה`, `מידה`, `יצרן`…
- סקריפט המרה → JSON-ביניים → `extract_lipskey.py` → `lipskey_catalog.dart`.
- מחיר: מאכלס `priceFor`/`StoreOffer` (לא ב-dims; ראה `related_info.dart`).

### מסלול C — התקבל יצוא-נתונים מובנה (JSON/API של ליפסקי)
- מיפוי-שדות ישיר ל-`LipskeyCatalogProduct` → `extract_lipskey.py`.

## 3. שערי-איכות שמונעים זיהום בקליטה (מ-§9/§13/§14)

כל באג-קליטה → בדיקה אוטומטית. השומרים הקיימים (catalog_regression_test / spec_assets_test)
חלים על polyroll; להכליל לליפסקי בקליטה:
1. **מק"ט ייחודי** — `skus.toSet().length == skus.length`.
2. **שם≠זבל** — לא SKU-כשם, לא שם-ריק, לא קוד-יצרן ב-nameHe.
3. **dims↔שם** — `dims['מידה']` תואם לאסימון-המידה בשם (תפס יישור-עמודות שגוי).
4. **צבע≠חומר** — ⚠️ קריטי: `color` הוא גימור-נראה. "נחושת"/"ניקל"/"פליז" בקטגוריית-חומר
   (אביזרי-נחושת/HDPE) = **חומר**, לא צבע. רק בברזים/גופי-תברואה = גימור.
5. **קטגוריה נקייה** — כל פריט בקטגוריה מאותו טיפוס (כלים לא בתוך אביזרים).
6. **תמונה קיימת** — כל `imageFile`/`specImageFile` קיים על דיסק (אין יתומים/שבורים).

- **החלטה:** הגל **שוחזר במלואו** (אפס שינוי-קוד) — לא מקמטים דאטה כפולה ששוברת גייט סמכותי בשביל 10 תיאורים.

**כלל לקטלוג הבא:** לפני העשרה, להצליב מול `lipskey_pdf_parity_test.dart` — כל מק"ט שמוצמד שם
