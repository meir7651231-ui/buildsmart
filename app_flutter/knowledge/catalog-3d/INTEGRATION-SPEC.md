# ספֵק אינטגרציה — מנוע PP-R פרמטרי → BuildSmart

> **קהל יעד:** ארכיטקט/צוות הפיתוח של בנייה-חכמה.
> **מטרה:** להטמיע את מנוע-האביזרים הפרמטרי (קטלוג→מידות→3D→תכנון-חיבור→כתב-כמויות) כמודול באפליקציה.
> **סטטוס:** אב-טיפוס עובד ומאומת (WebGL + Python). הפורט ל-Flutter = עבודה מוגדרת מטה.

---

## 0 · תקציר מנהלים

בנינו **מנוע-תכן טהור** שמחשב את *כל* מידות אביזר PP-R מ**חוקים הנדסיים** (OD·SDR·עומק-ריתוך+z) — **אפס נתוני-קטלוג, אפס תלויות, אפס I/O**. מהמידות נבנה 3D בזמן-אמת, בונים ממנו מסלול-חיבור מנותב ב-3D, ומהמסלול מפיקים **כתב-כמויות + מפרט-ביצוע** (מידות, ניכוי-חיתוך Z, פרמטרי-ריתוך, תמיכות, תקנים).

**למה זה חשוב ל-BuildSmart:** זה הופך קטלוג-שרשרת-אספקה סטטי למנוע-תכן חי — הלקוח בוחר אביזר ומקבל ויזואליזציה מדויקת, מתכנן קו, ומקבל רשימת-רכש + הנחיות-התקנה. הכל client-side, בלי שרת, בלי DB של מידות.

**המספרים:** 10 משפחות · דיוק ~1.3 מ״מ (רצפת עיגול-התקן, בלתי-נראה ב-3D) · 627 מוצרי-פולירול אימתו את היחסים · 0 תלויות-ריצה.

## 1 · חוזה-המנוע (הליבה לפורט)

פונקציה טהורה אחת. פורט ל-Dart = העתקה ישירה (אין state, אין async, אין packages).

```
generate(family: String, od: int) -> Map<letter, double>
```

**הבסיס האוניברסלי** (כל אביזר-ריתוך):
```
wall = od / SDR            (PN20 → SDR=6)
ID   = od − 2·wall          קדח-זרימה
B/D  = od·(1 + 2/SDR) ≈ 1.33·od   קוטר-חוץ האביזר
C    = od·0.97              קדח-שקע (הצינור נכנס)
F    = DEPTH[od]            עומק-ריתוך (טבלת DIN 8077)
```
`DEPTH = {20:14.5, 25:16, 32:18, 40:20.5, 50:23.5, 63:27.5, 75:30, 90:33, 110:37, 125:40}`

**צורה פר-משפחה** (z = מרכז→פנים, מגיאומטריה):
| משפחה | חוק |
|---|---|
| מצמד | `A = 2F + 2` |
| ברך 90°/45° | `z = R·tan(θ/2)`, `R=0.52·od`, `l = F + z` |
| מסעף (טי) | `z = B/2`, `E = 2(z+F)`, `A = z+F+B/2` |
| מתאם תבריג | `hex=1.95od`, `SW=0.87·hex`, `thread=1.05od`, `l=F+z+thL` |
| ברז כדורי | `D=1.6od`, `dk=0.67od≈DN`, `h=2.9od` |
| מצרה | קומפוזיציה `base(d1)+base(d2)` |
| פקק | `A=F+0.4od`, `cap=0.4od` |
| רוכב | `D=1.333od`, `d1≈2od`, `l=F+0.64od` |
| צווארון | `D=1.15od`, `D1=1.619od` (אוגן), `A=1.478od` |

מקור מלא + הוכחות: [`GEOMETRIC-CONSTRUCTION.md`](./GEOMETRIC-CONSTRUCTION.md).
מימוש-ייחוס: [`pure_engine.py`](./pure_engine.py) (`ENGINE` dict). פורט-JS זהה: [`prototypes/gen3d.html`](./prototypes/gen3d.html).

**אומגה (Ω) נדחית** — אין יחס-קטלוג נקי. **AQUATEC (682) + ליפסקי (322)** — 0% מידות בזיפ; דורש קטלוגים משלהם (אז אותה קונסטרוקציה תעבוד).

## 2 · מודל-נתונים מוצע (Dart)

```dart
enum Family { coupler, elbow90, elbow45, tee, adapter, valve, reducer, plug, saddle, collar }
enum Dir { up, down, left, right }

class Dims { final Map<String, double> letters; }          // פלט generate()

class RunElement {                                          // צומת ברצף
  final Family family;
  final int od;                                            // קוטר נומינלי
  final Dir dir;                                           // כיוון (לברך/טי בלבד)
}

class Route { final List<RunElement> elements; }           // המסלול המלא
```

המנוע (`generate`), פריסת-הרצף (`layout`), וההפקה (`bom`, `cutList`) — **כולן פונקציות טהורות** מעל המבנים האלה. אין coupling ל-Riverpod/UI. State = רק `Route` (רשימה) + `explode` (double) + `mode`.

## 3 · אלגוריתם תכנון-החיבור (turtle 3D)

הליבה של המסלול. פריסה של רצף-אביזרים למרחב 3D, עם ניתוב לכל כיוון וגדלים מעורבים.

**מצב-הצב:** `P` (מיקום), `F` (forward), `U` (up). `side = F×U`.

```
for each element:
  gap = explode · GAP · F                    # פיצוץ-מפרקים
  אם צריך צינור-מעבר: pipe(prevOD, od)        # taper אם הגדלים נבדלים
  B = dirVec(dir, F, U)                       # ⬆F,⬇-F,➡side,⬅-side על U
  emit meshes with frame(F, axisPerMesh, F×axis, P·S)
  P += ex·F + ey·(bendAxis)                   # התקדמות לפי exit-port המקומי
  if elbow:                                   # עדכון-בסיס אחרי פנייה
    F' = cosθ·F + sinθ·B ;  U' = rot(U) ;  Gram-Schmidt(U ⟂ F)
```

**עקרונות:**
- כל אביזר נבנה במסגרת-מקומית (כניסה ב-0 לאורך +X, הפנייה ב-+Y). מסגרת-3D ממפה local→world.
- **גדלים מעורבים:** צינור-המעבר בין שני אביזרים מתחדד אוטומטית כשהקטרים נבדלים (`taperGeom`).
- **כיוון:** ברך מנתבת את המסלול; טי/רוכב מוציאים הסתעפות — לכיוון שנבחר.
- **פיצוץ:** מרווח מצטבר לאורך F לפני כל אלמנט → כל מפרק נפרד לאורך המסלול.
- מצלמה: fit של כדור-חוסם (bounding-sphere) על הרצף המנותב.

מימוש-ייחוס מלא ומאומת: `buildPlan()` ב-[`prototypes/gen3d.html`](./prototypes/gen3d.html).

## 4 · 3D — גישת-הרינדור

**באב-הטיפוס (Preact/web):** WebGL בעבודת-יד, בלי ספריות (CSP-safe). פרימיטיבים: `revolve(profile)` (מחרטה), `hexRod`, `sphere`, `tube`. שיידר PBR-lite, מסגרות mat4, אורביט. ~200 שורות, 0 תלויות.

**ל-Flutter (app_flutter):** שתי דרכים —
1. **`flutter_gl` / `three_dart`** — פורט ישיר של הרשתות (הפרופילים כבר מוגדרים כ-2D→lathe). מומלץ לנייטיב.
2. **מנוע-רינדור מינימלי משלנו** — הרשתות פשוטות (גופי-סיבוב); אפשר לצייר עם `CustomPainter` + מטריצות ידניות לתצוגת-סקיצה, או `Impeller`. קל אם רוצים בלי package.

הגיאומטריה עצמה (הפרופילים) = פלט טהור מ-`generate()`, בלתי-תלוי-פלטפורמה. **הפרדת-הטוהר הזו היא הנקודה:** אותו מנוע מזין web-WebGL, Flutter-GL, או הפקת-שרטוט.

## 5 · פיצ׳ר כתב-כמויות + מפרט-ביצוע

מהמסלול (`Route`) מפיקים מסמך-עבודה (ראה `genDoc()` באב-הטיפוס). תוכן, כולו נגזר-מנוע:
1. **כתב-כמויות (BOM)** — אביזרים לפי (משפחה×קוטר)×כמות + צינור לפי קוטר×אורך.
2. **טבלת-מידות** — כל אות לכל אביזר-ייחודי.
3. **ניכוי-חיתוך (Z):** `אורך-חיתוך = מרחק בין-מרכזים − Z₁ − Z₂`, `Z = (מרכז→פני-שקע) − F`.
4. **פרמטרי-ריתוך (DVS 2207-11):** חימום/חיבור/קירור לפי קוטר, 260°C. *ערכי-ייחוס — לאמת מול דף-יצרן.*
5. **מרווחי-תמיכה** · **מבחן-לחץ** (1.5× עבודה) · **תקנים** (DIN 8077/8078, ISO 15874, DVS 2207-11).

זה מחבר את המנוע לערך-העסקי של BuildSmart: **בחירת-אביזר → רכש (BOM) → התקנה (מפרט)**.

## 6 · נתיב-אינטגרציה ל-app_flutter

**מיקום מוצע:** מודול חדש `app_flutter/lib/features/fittings/` —
```
fittings/
  engine/       generate(), base(), families  ← פורט טהור מ-pure_engine.py (בלי תלויות)
  layout/       turtle3d.dart  ← §3, פונקציה טהורה Route→List<PlacedMesh>
  geometry/     revolve/tube/sphere/hexRod  ← פרופילים→רשתות
  render/       3D widget (flutter_gl או CustomPainter)
  plan/         bom.dart, cut_list.dart, weld_table.dart  ← §5, טהור
  ui/           picker + chain editor + explode slider + export
  state/        route_provider.dart (Riverpod) — מחזיק Route + explode + mode
```

**עקרונות-הטמעה:**
- `engine/`, `layout/`, `plan/` = **Dart טהור, ניתן ל-unit-test 1:1** מול `pure_engine.py` (אותם מספרים).
- Riverpod מחזיק רק את ה-`Route` (state מינימלי); הכל נגזר.
- אין תלות-רשת/DB — המנוע הוא המקור. (הקטלוג משמש רק לבחירת-מוצר/מק״ט; המידות מחושבות.)
- תואם ל-`knowledge_protocol_test` ולזרימת ה-Flutter (`flutter analyze` + `flutter test`).

**Preact (`app/`, ה-live):** אם רוצים גם שם — הפורט-JS כבר קיים (`gen3d.html`), ניתן לעטוף כרכיב-אי (island) עד ה-cutover.
