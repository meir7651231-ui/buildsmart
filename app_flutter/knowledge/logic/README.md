# knowledge/logic — the engine layer, opened

> DECOMP-DEPTH phase L output. Auto-generated by the **read-only** logic
> decomposer (`tools/atom/decompose --logic <file> --out app_flutter/knowledge/logic`).
> One directory per module; do not hand-edit the generated files — re-run the tool.

Where `knowledge/screens/` opens the **widgets**, this opens the **logic/engines**
the widget graph only named. For each function: **object** (signature + constants)
· **connections** (reads · writes · calls · called-by · gated-by, with transitive
`↝` markers) · **behaviour** (the algorithm as steps) · **floor** · **contract**
(input→output · precond · null-when · purity).

Each module dir holds `module.logic.json` (the machine model), one
`<fn>.logic.md` per function (private fns prefixed `p_`), and — where the
decomposer surfaced structural debt — a `HARD-CASES.md` of owner-decisions.

**Guards:** the decomposer is read-only (parses source, emits knowledge, never
touches app code). Debt (god-modules, hidden caches, runtime registry mutation,
data-welded-to-flow) is **documented + raised as owner-decisions**, never
refactored. Safety output = reference-value + caveat (M5).
