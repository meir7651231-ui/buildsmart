## HARD RULE #3 — error folds to EMPTY, never a crash

A `.when(error: …)` returns the **same empty view** the empty-data branch does.
Both `.when` consumers obey it (2/2). Example — `home_shell` `dir.when`:

```
error: (_, __) => _emptyHint(),          // error → the empty view (#3)
data:  (entries) { if (entries.isEmpty) return _emptyHint(); … }  // empty in data
```

## The split (step 85) — no uniform async contract

The app is **overwhelmingly synchronous**: **300 of 310 providers are sync**
const state (catalog, cart, personas). They have **no `AsyncValue`, no loading,
no error path — because they cannot fail**. Only the **10 async** providers
(7 local-compute Future + 3 firestore Stream) flow through `AsyncValue` + `.when`.
So there is **no single async contract to assume** — a sync provider's missing
error-path is a documented *gap by design*, not a defect.

## The typed failure surface (step 84)

The repos map raw Firebase failures to **typed, neutral exceptions** before the
UI folds them to empty:

- `OrderFunctionsException` · `ClaudeException` · `UploadFunctionsException` ·
  `AuthGatewayException`.
